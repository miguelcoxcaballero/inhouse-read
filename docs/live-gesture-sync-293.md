# 1.7.293 — live shelf gestures and shared reading positions

The previous direct-room transport published a book's placement after release. This change streams its actual displayed transform while it is held, including nearby books moved by the gesture. Positions use metres relative to the physical shelf bay, quaternions preserve orientation, and Drive file IDs identify books whose local IDs differ between installations.

The transport follows the [production Inhouse Notes v5 design](https://github.com/miguelcoxcaballero/inhousenotes/blob/main/live-collaboration-v5.js): encrypted private Drive rendezvous, an ordered reliable WebRTC channel for complete state, a separate ordered reliable interactive channel for gestures and health checks, and an account-scoped BroadcastChannel with an initial-state request for local tabs. Late ICE candidates are delivered through refreshed encrypted SDP and added to the existing negotiation. Temporary disconnections receive a grace period; a failed route is renegotiated. Each JavaScript realm has its own identity, while a resumed session retains its motion clock and its own mailbox. OAuth credentials are not sent to peers.

Rust validates account/gesture/sequence/size bounds, rejects duplicate and obsolete motion frames, limits active actors, expires abandoned previews and interpolates physical poses over 65 ms. A final durable snapshot remains authoritative. Remote ownership continues through the gesture and its settling frames: a background snapshot/metadata refresh waits instead of clearing the active preview. Remote previews never become local gesture commits. A motionless held book renews its lease without a remote GPU render loop. The browser adapter owns WebRTC, crypto, storage and Three.js handles; meshes, texture resolution and materials are unchanged.

Reading percentage, locator and reading timestamp now travel together in a `readingPosition` register, retaining scalar fields for older clients. Successful local reading commits enter the direct path without waiting for Drive. Local reading clocks advance past the previous timestamp, including one received from a slightly faster device. Closing an unchanged reader does not stamp its old page over newer progress received from the other device. Appearance/placement patches do not manufacture a new reading timestamp, and a stale legacy reading file cannot undo a shared position on a timestamp tie.

A room refresh received during local or remote motion is retried after the interaction; it is no longer discarded. Completed remote interpolation is distinguished from local interaction. A new semantic placement takes the normal layout path before adopting its physics, avoiding double translation. Passive recalculation/rounding cannot supersede a previously shared physical room; an explicit local gesture can. Legacy room schema upgrades remain allowed.

- A general run covered 6,933 unit cases: 6,932 passed and one old differential expectation failed because it lacked the new reading-position contract. The JavaScript reference now explicitly models that contract; its 70 seeded scenarios and the affected native/storage/reader/transport tests passed in a subsequent 273-case run. An additional 57-case run covered scene scheduling, metadata adoption and library compatibility. Later physical-authority tests and final browser results are recorded below.
- Browser tests use the real built app, real WebRTC/WebCrypto, separate IndexedDB stores and a shared binary-preserving Drive HTTP fixture. Drive manifest writes are delayed five seconds during direct-delivery assertions. A loopback TCP TURN fixture is test-only because this environment's managed Chromium disables non-proxied UDP. Browser policy and system proxy are unchanged.
- The production configuration uses STUN and the durable Drive fallback, as before; no production TURN service is provisioned. The local relay measurements do not certify arbitrary mobile networks or restrictive NATs.
- The shared updater remains at canonical revision `6621ca1dbb519d171d723f118052e42ef5d5c001`. No APK or updater-channel catalog is published by this change.

Final native/browser verification:

- **320/320 targeted unit cases passed**, 22 files, on the final native build. Includes the 70 seeded differential scenarios, abandoned/out-of-order gestures, a motionless lease with no redraw, remote gesture ownership, passive physics authority, geometry/import upgrades, semantic placement guards, monotonic/invalid-clock repair, concurrent reading and close/restore behavior.
- **4/4 browser cases passed without retries**, three minutes: independent mobile/desktop installations with live held movement; local tabs with RTC unavailable; exact reader-return layout in frontal and isometric views. A reverse appearance edit arrived in 79 ms; the settled inclination was observed in 24 ms after the source's quiet wait. These are fixture measurements, not physical-phone or WAN latency guarantees.
