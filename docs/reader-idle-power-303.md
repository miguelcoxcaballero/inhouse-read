# Reader workload isolation — 1.7.303

Opening a reader now suspends the shelf unconditionally. Previously the scene could continue scheduling frames while inactive if motion/lighting was still settling; explicit flushes could also paint the hidden room. Inactive scenes now reject both scheduled and forced draws, cancel pending frame/program polling and reset the physics clock. Poses, geometry, textures and dirty state remain available for the existing return animation. This does not lower rendering quality or reconstruct the shelf.

Shelf/startup idle callbacks park on a screen-ownership signal rather than polling while reading. Cover-font matching yields at its existing numerical boundaries; plant texture work and optional shader preparation use the same parked idle scheduler. Detached library parsing waits before opening another parser and at page/section boundaries. The visible reader still computes its own missing reading metrics once; that result is persisted with a content-revision guard and replaces the redundant detached count. Reading progress and live sync remain active. Incoming refresh notifications are coalesced while reading, so they do not reread the full library or rebuild the hidden shelf; Rust applies the pending refresh after the return animation.

The Rust reader lifecycle no longer automatically warms a previously used natural voice when a book opens. Pausing audio no longer immediately warms/prepares speech again. Opening audio controls and pressing Play retain their existing explicit preparation paths and voice quality.

Verification covers idle GPU/animation activity in production PDF/EPUB readers, a previously used natural voice remaining dormant until requested, working page turns/audio controls, exact shelf layout across open/close in both views, cached count revision guards, and suspended unfinished scene motion resuming on return. The tests use Chromium software WebGL, not a physical Android thermal or battery measurement. A settled reader without these background tasks was already idle in the baseline; these changes close the additional workload paths rather than claiming a measured universal battery percentage.

Targeted validation: 254 unit cases across 15 suites passed, including the real compiled Rust reader/return coordinators. Production browser checks cover PDF/EPUB idle reading and explicit audio, both shelf views, page/time indicators, and native/fallback return-canvas ownership. In the instrumented eight-second idle samples there were zero RAF callbacks, zero WebGL draws and zero worker messages (about 61–69 ms of main-thread work). These are workload checks, not device power measurements.
