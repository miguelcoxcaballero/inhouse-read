# 1.7.298 — one physical revision for live and saved rooms

The live renderer and the saved solver state previously had separate lifetimes. A final motion frame expired after five seconds even if its durable snapshot had not arrived. A stale frame could also regain ownership after its actor expired, and a cloud refresh cleared previews before their corresponding physical room was installed. These paths could show an old position again or a locally recalculated approximation.

The Rust room protocol now fences gestures with a canonical physical revision. Frames name the room they started from; a final frame names the room it commits. A completed preview remains stationary until the receiving solver has installed a physical checkpoint. Checkpoint-first and frame-first delivery use the same handoff. Old-base frames cannot override a newer installed room. Sequence fences survive expired actors, and a connection loss retains a final preview awaiting its checkpoint. Idle retained previews do not run an animation loop. Legacy frames without revision fields remain supported, so both devices need this version for the new guarantees.

Local persistence and cloud state now use the same bay-relative physical coordinates and stable Drive identities. The revision excludes pixel-rounded semantic anchors but includes physical positions, orientations, geometry and cabinet identity. It is a deterministic comparison token, not authentication; existing account validation and encrypted transport remain responsible for authentication. A passive render or resize preserves an already received physical checkpoint instead of writing solver roundoff as a local change. Valid restored bodies are not clamped again on initialization. The receiving renderer acknowledges only an installed, restored solver state, not merely receipt of a network packet. That acknowledgement verifies geometry, solid signatures and the actual restored pose; a later local settlement cannot masquerade as adoption of an incompatible remote snapshot.

Gesture frames retain the complete set of affected objects until the gesture ends, including a neighbour that returns to its initial position. Books without a Drive identity stay in local persistence and are excluded from the shared physical room and its revision. Applying a shared room retains those device-only poses for the same cabinet, rather than publishing unmappable local IDs or deleting them. Existing field-register conflict resolution remains the final authority for saved state; provisional frames cannot supersede its installed physical revision.

Regression coverage includes delayed durable delivery beyond the old five-second expiry, checkpoint/frame delivery in either order, unchanged careful put-back, expired/replayed sequences, competing preview branches, disconnection, viewport changes, exact canonical X/Y/angle persistence, and unuploaded local books. Browser tests use independent mobile/desktop Chromium contexts, actual RTC via a local test TURN server, and simulated Drive. The delayed-checkpoint test blocks Drive and the reliable snapshot channel while allowing interactive motion, resizes the receiver, then releases the checkpoint and reloads it. It also replays a pre-commit frame after reconnecting. Existing decorated-room, touch-drag and RTC-blocked fallback cases remain active.

This is not a physical-phone/WAN latency benchmark. Network latency still separates live samples; the stationary committed room is shared, while interpolation is purely visual. This release changes neither mesh/texture quality nor Android updater channels/APKs.
